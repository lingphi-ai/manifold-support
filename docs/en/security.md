# Security

Manifold is a local access layer, not a token marketplace. It helps developers
keep real provider credentials out of project directories, shell history, CI
logs, and shared issue reports while still testing real business logic through
real upstream providers.

## Local gateway boundary

The gateway binds to `127.0.0.1`. Manifold enforces loopback host configuration
and is not designed to expose the gateway to a LAN or public network. Every
request requires a Manifold gateway key (`ldd_…`, 32 random bytes) or an active
Local Session Key.

The Settings window runs under a strict Content-Security-Policy. Provider CLIs
are spawned with `shell: false`, a 120-second timeout, and a 10 MB output cap,
and are aborted when the request is cancelled. Application logs redact sensitive
values — including `apikey`, `authorization`, `prompt`, `messages`, `response`,
`stdout`, and `stderr`, and any `mf_session_`, `ldd_`, `sk-`, or `AIza` tokens.

## Provider credentials

Provider credentials stay on the user's machine. `config.json` and the secret
store are written with `0600` permissions. Remote API keys are stored in
Manifold's local secret store. When Electron safeStorage and the operating system
keyring are available (for example the macOS Keychain), values are encrypted
before storage. If OS-level encryption is unavailable, Manifold falls back to
`0600` local plaintext and logs a warning.

Provider keys are never returned through the Manifold API. Clients only receive
Manifold gateway credentials.

## URL safety

Hosted remote provider URLs must be safe HTTPS URLs. Manifold blocks loopback,
private, link-local, metadata, wildcard-DNS, and embedded-IP host patterns for
hosted provider URLs so a malicious custom provider cannot receive a real
provider key through SSRF-style configuration.

Ollama, LM Studio, and vLLM are explicit local-server presets. They are allowed
to use localhost HTTP because they are meant to run on the same machine and can
be keyless.

Provider-native passthrough is also constrained: redirects are not followed, and
the passthrough path must remain inside the configured provider origin. For
remote providers, native forwarding is restricted to **GET and POST only** — a
security allow-list rejects any other HTTP method, even though the underlying
`ALL /v1/native/:provider/*` route accepts any method at the routing layer.

## Local Session Keys

Local Session Keys are short-lived credentials generated by Manifold for local
tools such as Claude Code, test runners, and project scripts. They start with
`mf_session_`, are shown once, and can be revoked. Only a SHA-256 hash of the
key is stored — never the raw value — and verification is timing-safe and
fail-closed.

Minting a key from a CLI uses the "Pair a CLI" flow, which requires an explicit,
human-armed pairing step so keys cannot be minted silently.

In Pro, a Local Session Key can include:

- label;
- TTL;
- optional project name;
- allowed route names;
- allowed provider ids;
- request count and last-used timestamp;
- audit events for create, revoke, bulk revoke, and cleanup.

Example:

```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:17680
export ANTHROPIC_API_KEY=mf_session_<short-lived-key>
```

The key authenticates a client to Manifold on `127.0.0.1`. It does not expose the
real Anthropic, OpenAI, DeepSeek, OpenRouter, or other provider API key.

## What session keys are not

- They are not Anthropic, OpenAI, DeepSeek, OpenRouter, or other provider API
  keys.
- They are not model credits or prepaid usage.
- They do not bypass provider accounts, provider billing, or provider terms.
- Manifold does not sell, lease, or broker third-party model tokens.
- They do not let another machine call your gateway unless you deliberately
  break the local-only boundary outside Manifold.

## Recommended workflow

1. Add providers in Manifold and keep their real credentials in Manifold local
   storage.
2. Create one Local Session Key per project or development task.
3. Use a short TTL such as one hour, one day, or seven days.
4. Add route/provider allow-lists when the tool only needs specific access.
5. Put `mf_session_<short-lived-key>` into the local tool that needs gateway
   access.
6. Revoke the key when the task ends, before sharing the project, or whenever it
   may have entered logs.

## License and billing safety

Pro is unlocked by short-lived, signed entitlement tokens scoped to the Manifold
product and device. Packaged builds always enforce licensing. Development
overrides are ignored in packaged builds.

Billing and license links opened from the app are restricted to allow-listed
HTTPS hosts such as Lingphi and Stripe.

## Issue hygiene

When filing issues, redact provider keys, Manifold gateway keys, Local Session
Keys, license keys, private prompts, raw request bodies, and raw provider
responses unless a maintainer explicitly asks for a sanitized sample.
